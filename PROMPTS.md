# PRPilot — AI Review Prompts

## System Prompt

Used for every chunk review call. Set as the `systemInstruction` in the Gemini API config.

```
You are PRPilot, an expert code reviewer. You review pull request diffs and provide precise, actionable feedback.

RULES:
1. Focus ONLY on the code that was ADDED or MODIFIED in the diff (lines starting with "+"). Do not comment on deleted lines or unchanged context.
2. Every comment must reference a specific line number from the new (right) side of the diff.
3. Be concise. Each comment title must be ≤120 characters. Each body must be ≤1000 characters.
4. Use the severity scale exactly:
   - "critical": Security vulnerability, data loss risk, crash/exception, incorrect logic that breaks functionality.
   - "warning": Performance issue, potential bug in edge case, missing error handling, code smell that harms maintainability.
   - "suggestion": Style improvement, refactoring opportunity, better naming, missing documentation.
   - "praise": Genuinely good pattern, clean abstraction, thoughtful error handling. Use sparingly (max 2 per chunk).
5. If suggesting replacement code, include it in the "suggestion" field. Keep suggestions ≤500 characters.
6. Do NOT hallucinate issues. If the code looks correct, return fewer comments rather than fabricating problems.
7. Do NOT comment on formatting, whitespace, or style preferences unless they cause a bug.
8. Do NOT include comments about code that is not in the diff.
9. Respond ONLY with valid JSON matching the required schema. No markdown, no preamble, no explanation outside the JSON.
10. The severity_counts object must accurately reflect the counts of each severity in the comments array.
```

## User Prompt Template

Sent as the `contents` for each diff chunk. Variables are interpolated by the processor.

```
Review this pull request diff chunk.

**Repository:** {{repo_full_name}}
**PR #{{pr_number}}:** {{pr_title}}
**Author:** {{pr_author}}
**Strictness:** {{strictness}}

{{#if custom_instructions}}
**Additional review instructions from the repository owner:**
{{custom_instructions}}
{{/if}}

**Diff (file: {{file_path}}):**
```diff
{{diff_content}}
```

Provide your review as JSON matching the required schema.
```

### Variable descriptions

| Variable | Source | Example |
|---|---|---|
| `repo_full_name` | `repos.full_name` | `"octocat/hello-world"` |
| `pr_number` | `review_jobs.pr_number` | `42` |
| `pr_title` | `review_jobs.pr_title` | `"Fix null pointer in parser"` |
| `pr_author` | `review_jobs.pr_author` | `"developer123"` |
| `strictness` | `repo_settings.strictness` | `"balanced"` |
| `custom_instructions` | `repo_settings.custom_instructions` | `"Focus on SQL injection risks"` |
| `file_path` | Parsed from diff | `"src/lib/parser.ts"` |
| `diff_content` | Raw unified diff for this chunk | `"@@ -10,5 +10,8 @@\n ..."` |
| `chunk_count` | Total chunks analyzed | `4` |
| `review_duration` | Review wall-clock duration in seconds (`Math.round(review_duration_ms / 1000)`) | `18` |

*Note: `review_duration` in comments is the milliseconds value (`review_duration_ms`) divided by 1000, rounded.*

### Strictness behavior

The `strictness` value in the prompt instructs the model:

| Level | Guidance embedded in system behavior |
|---|---|
| `relaxed` | Only flag critical and clear warnings. Skip style and minor suggestions. |
| `balanced` | Flag all genuine issues. Include helpful suggestions. Default behavior. |
| `strict` | Flag everything including minor style issues, missing docs, and suboptimal patterns. Be thorough. |

The model sees the word in the prompt and adjusts its threshold accordingly.

## Severity Scale

| Severity | Icon | Meaning | Risk weight |
|---|---|---|---|
| `critical` | 🔴 | Security flaw, crash, data loss, broken logic | 25 |
| `warning` | 🟡 | Potential bug, perf issue, missing error handling | 10 |
| `suggestion` | 🔵 | Style, refactoring, documentation | 3 |
| `praise` | 🟢 | Good pattern, clean code | 0 |

---

## Risk Score Formula

Computed by the processor after merging all chunk results. Not generated by the AI.

```
raw_score = (critical_count × 25) + (warning_count × 10) + (suggestion_count × 3)

risk_score = min(100, raw_score)
```

### Examples

| Scenario | Critical | Warning | Suggestion | Raw | Score |
|---|---|---|---|---|---|
| Clean PR | 0 | 0 | 2 | 6 | 6 |
| Minor issues | 0 | 2 | 5 | 35 | 35 |
| Risky PR | 2 | 3 | 4 | 92 | 92 |
| Dangerous PR | 3 | 5 | 10 | 155 | 100 |

### Interpretation

| Score range | Label | Dashboard color |
|---|---|---|
| 0–20 | Low risk | Green |
| 21–50 | Moderate risk | Yellow |
| 51–80 | High risk | Orange |
| 81–100 | Critical risk | Red |

## Summary Comment Template

Posted as the PR review body on GitHub after all chunks are processed.

```markdown
## 🤖 PRPilot Review

**Risk Score: {{risk_score}}/100** {{risk_label}}

### Summary
{{summary}}

### Findings
| Severity | Count |
|---|---|
| 🔴 Critical | {{critical_count}} |
| 🟡 Warning | {{warning_count}} |
| 🔵 Suggestion | {{suggestion_count}} |
| 🟢 Praise | {{praise_count}} |

{{#if has_critical}}
> ⚠️ **Critical issues found.** Please address them before merging.
{{/if}}

---
<sub>Reviewed by [PRPilot](https://github.com/apps/prpilot) • {{review_duration}}s • {{chunk_count}} chunk(s) analyzed</sub>
```

## Gemini API Configuration

```typescript
import { GoogleGenAI, Type } from "@google/genai";

const ai = new GoogleGenAI({});

const response = await ai.models.generateContent({
  model: "gemini-3.8-flash",
  contents: userPrompt,
  config: {
    systemInstruction: SYSTEM_PROMPT,
    responseMimeType: "application/json",
    responseJsonSchema: {
      type: Type.OBJECT,
      properties: {
        chunk_summary: {
          type: Type.STRING,
          description: "Brief summary of what this chunk of code does",
        },
        comments: {
          type: Type.ARRAY,
          description: "Inline review comments for this chunk (max 20)",
          items: {
            type: Type.OBJECT,
            properties: {
              file_path: {
                type: Type.STRING,
                description: "Relative path of the file in the repo",
              },
              line_number: {
                type: Type.INTEGER,
                description: "Line number in the new (right) side of the diff",
              },
              severity: {
                type: Type.STRING,
                enum: ["critical", "warning", "suggestion", "praise"],
                description: "Severity level of the issue",
              },
              title: {
                type: Type.STRING,
                description: "One-line summary of the finding (<=120 characters)",
              },
              body: {
                type: Type.STRING,
                description: "Detailed explanation of the issue and why it matters (<=1000 characters)",
              },
              suggestion: {
                type: Type.STRING,
                description: "Suggested replacement code, if applicable (<=500 characters)",
              },
            },
            required: ["file_path", "line_number", "severity", "title", "body"],
          },
        },
        severity_counts: {
          type: Type.OBJECT,
          properties: {
            critical: { type: Type.INTEGER },
            warning: { type: Type.INTEGER },
            suggestion: { type: Type.INTEGER },
            praise: { type: Type.INTEGER },
          },
          required: ["critical", "warning", "suggestion", "praise"],
        },
      },
      required: ["chunk_summary", "comments", "severity_counts"],
    },
    temperature: 0.2,        // low temperature for consistent reviews
    maxOutputTokens: 4096,
  },
});
```

**Temperature 0.2**: Chosen for consistency — reviews should be deterministic and not creative. Higher temperatures cause the model to invent non-existent issues.

**Max output tokens 4096**: Sufficient for 20 inline comments with suggestions. The structured schema keeps output compact.
